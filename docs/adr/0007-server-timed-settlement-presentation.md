# 实际结算与服务端计时的收付展示分离

分组跑马结果、底池派彩及逐笔惩罚动画需要统一顺序，同时不能让浏览器动画决定筹码是否入账。保持服务端实际结算的事务性与幂等性，另行持久化必要的展示阶段、期限、实际转账与余额快照；第一组结果先展示，但不提前结算半手，也不公开尚未发出的牌。

相较于客户端自行延迟显示最终快照，这会增加展示状态及恢复逻辑，但能保证各视角顺序一致、下一手不截断展示，且补码、买出、附加玩法同时发生时金额仍正确。亮牌与重买入期限从统一的展示结束时刻起算，不等待客户端动画确认；刷新与重连按当前阶段恢复，不重复实际转账或补播错过的动效。

新发手牌记录展示版本，未带版本的旧在途手维持原有发牌节奏及 5 秒亮牌期限。第一组中间结果使用 PokerKit 已发牌及既定分池资格计算，仅比较牌力，不推进第二组、不触发筹码支付；完整结算仍由原引擎和奖励账目完成。
