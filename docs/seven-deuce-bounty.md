# 2–7 杂色奖励：规则调研与设计澄清

状态：Q1–Q14 已全部确认并实现，本地构建、128 项后端测试及 45 项浏览器测试通过；尚未部署。
调研日期：2026-09-18。

## 用户已指定的目标

- 增加 2–7 杂色奖励，限定两张底牌为不同花色的 2 和 7。
- 创建房间时可以在选项中开启。
- 游戏持续期间可以通过房间配置关闭或开启；修改从下一手生效，当前手保持原规则。
- 创建房间界面在该选项后方使用信息按钮展示规则。
- 中奖时在屏幕中央公屏展示“玩家A获得2-7奖励+X”，使用酷炫的奖励 Badge 效果。
- 先查询常见规则，再澄清设计。

## 外部规则依据

这是一项附加奖励约定，不能把某个平台的全部细则视为统一标准。

- [Poker Now 官方说明](https://www.pokernow.com/blog/the-7-2-game-in-poker-adding-a-twist-of-fun-to-the-classic-card-game)：事前约定每人奖励，本手获发牌的玩家参与；持 7–2 在摊牌或迫使其他人弃牌后获胜，公开底牌才能领取。玩家可以选择不亮牌并放弃奖励。余额不足者支付余下余额后视为结清。奖励数额可以配置。
- [PokerCine 规则介绍](https://pokercine.com/how-to-play-poker/poker-terms/7-2-game/)：介绍经典仅限杂色的版本，奖励常见为每人 1–5 个大盲；同花是否纳入由牌桌约定。该文章是规则介绍，不是统一赛事规则。
- [CoinPoker 官方版本](https://coinpoker.com/games/seven-deuce/)：同花和杂色都计入、每人 5BB、使用桌上筹码之外的预缴奖励、自动公开中奖底牌，并规定多个 7–2 赢家平分奖励。这里只用于展示变体差异，不代表本项目采用。
- [一份私人牌局规则](https://thatsnotpoker.blogspot.com/2010/12/revised-seven-deuce-rules.html)：要求独赢主池，且允许个人退出附加奖励。仅证明边界可由牌桌另行约定，不作为通用标准。

示例：六名玩家参与，约定每人奖励 2 筹码。A 持 7♠2♣ 令其他人全部弃牌，并按约定亮牌；其他五人各支付 2，A 在底池之外额外获得 10。示例假定每位付款者余额充足。

## 实施前核实的产品边界

- 原房间配置只能由房主在两手之间修改，正在进行手牌或 Straddle 询问时不能保存（`backend/game.py` 的 `settings` 分支）。本次仅放开奖励开关及金额的局中修改。
- 发牌时已有 Run It Twice 开关快照；逐手固定奖励规则可采用类似边界。
- 原“无需摊牌获胜”不强制公开底牌，“自愿亮牌”使用结算后的五秒窗口。本次中奖时自动公开两张，领域词汇及代码均已记录该例外。
- 现有“赢池次数”要求独赢主池；发两次牌须独赢两组主池，不要求赢得边池。用户已确认奖励使用相同主要口径，但奖励排除未形成底池的情况。
- 现有净输赢按买出、持有筹码和买入计算。原“被清台”依据底池分配后、补码及离座前的零筹码状态；本次已把奖励扣款纳入清台判定，领域词汇和成就说明同步更新。

## 第一轮已确认决策

1. Q1：奖励以每位付款玩家支付的固定筹码数配置。开启时默认填入一个大盲对应的筹码数，房主可修改。
2. Q2：以本手实际获发底牌名单确定参与者，其他玩家均支付，包括后来弃牌或断线者；观战、AWAY、等待下一手加入的玩家不支付。不提供本手玩家单独退出奖励的选项。
3. Q3：独赢主池才触发。其他玩家全部弃牌也算，仅赢边池、主池平分、未形成底池而仅退回投入均不触发。发两次牌须独赢两组主池，不要求赢边池，整手只奖励一次。用户补充：创建房间选项后方增加规则信息按钮。
4. Q4：满足条件时自动公开赢家的两张底牌并结算，不要求手动领取。
5. Q5：正常底池结算后，从其他玩家桌上筹码扣除并转给赢家；单独记录奖励明细，计入房间净输赢。
6. Q6：默认关闭。由房主在创建房间或游戏期间修改，游戏期间允许随时提交，修改从下一手生效，当前手保持原规则；界面提示下一手开启或关闭。

已将奖励术语及自动亮牌例外写入 `CONTEXT.md`，全部规则同步至正式需求与验收文档。

## 第二轮已确认决策

- Q7：先分配底池，再支付奖励，最后处理离座及排队补码。每人实际支付不超过此时剩余桌上筹码，余额不足付清余下部分，零余额付零，不欠账也不自动补码。
- Q8：奖励支付后筹码归零也计一次被清台，与底池输光合并为每人每手最多一次，并进入现有重买入等待流程。已同步扩展领域词汇表定义。
- Q9：奖励使用正整数固定筹码。首次开启时填入当前大盲对应数额，此后保留已保存金额；改盲注、执行 Straddle、关闭再开启均不自动修改奖励。
- Q10：进行中只放开奖励开关及金额修改；其他房间设置仍在两手之间修改。奖励修改记录房间日志，并向所有人展示本手有效规则及下一手变更提示。
- Q11：开始准备一手并进入 Straddle 询问时，就固定该手奖励规则；询问期间的修改适用于随后的一手。若准备过程被取消，则新的准备过程采用最新配置。
- Q12：用户修订中奖反馈为屏幕中央公屏“玩家A获得2-7奖励+X”，使用酷炫的奖励 Badge 效果。创建房间和房间配置中的信息按钮、房间奖励状态与每人金额、手牌历史赢家和各人实付明细继续纳入方案；底池获胜数额保持原义。信息按钮不切换开关、不提交创建表单。

规则弹窗包含：仅限 2–7 杂色；独赢主池，发两次牌须独赢两组主池；仅赢边池、主池平分或未形成底池不奖励；自动公开两张底牌；本手其他获发底牌者支付，包括已弃牌玩家；余额不足付清剩余筹码且不欠账；奖励扣光计被清台；修改从下一手生效，Straddle 询问已开始的一手保持原规则。

## 最后一轮已确认决策

- Q13：屏幕中央使用黑金徽章，中心为交叠的 7/2 牌面与醒目奖励金额，辅以金色光环和少量星点；显示“玩家A获得2-7奖励 +X”，X 为各人实付之和。在线玩家及观战者同步看到。总时长约 3 秒，短促放大入场、停留、淡出；无遮罩，不抢焦点、不拦截操作，不延长发牌等待，下一手实际发牌时收起。只播放新发生的奖励事件，刷新和重连不补播旧事件；系统减少动态效果时静态展示相同时长。房间已有模态框保持在公屏上方。该短暂居中展示是既有桌心不展示赢家列表约定的明确例外，不增加永久结果面板。
- Q14：用户明确修订为效果不变，奖励金额写 0。实际奖励合计为零时仍自动公开赢家两张底牌、记录各人零实付，播放与正奖励完全相同的 Badge，文案“玩家A获得2-7奖励 +0”；不降级成普通提示。

设计已达成一致并获准实施，无未决产品选择。此次常规功能不另建 ADR。

## 实施与验收范围

- 新旧房间默认关闭，已在进行且未保存奖励规则的旧手牌不追发奖励。恢复时使用准备发牌阶段保存的本手开关和金额，不读取后续房间修改来重算旧手。
- 两张不同花色的 7/2 才匹配；同花、其他底牌及公共牌出现 7/2 不匹配。翻牌前全弃、正常摊牌、主池与边池赢家不同、主池平分、双发独赢两组、仅赢一组、仅赢边池、无底池分别验证。
- 扣款只针对本手获发底牌名单，排除赢家；已弃牌、断线及待离座者仍结算，AWAY、观战和下一手新入座者不扣款。验证足额、部分余额、零余额，玩家余额非负且房间筹码守恒。
- 先分池再扣奖励，再判定清台、保存历史、处理离座和排队补码。奖励扣到零与底池输光每手合计最多清台一次，立即补码不抹除清台。
- 每手保存奖励资格、名义每人金额、每人实际收付及总额。获池金额单独保留，本手净输赢含奖励；不得将奖励记为买入或买出。重连、重启、重复结算及成就重算均不得重复转账或计数，落库失败需整手原子回滚。
- 结算前奖励候选底牌保持原隐私规则，结算时自动公开赢家两张并写入公开历史；未中奖玩家的隐私不因奖励功能改变。
- 房主权限、金额整数边界、盲注变化保留金额、关闭重开保留金额、进行中仅修改奖励字段、Straddle 询问期间变更、取消准备后重新准备均需覆盖。下一手规则对所有人可见。
- 验证创建页和房内规则信息按钮：点击不提交表单、不切换奖励开关，手机能正常打开及关闭规则弹窗；旧配置与规则说明一致。
- 中央公屏向在座玩家和观战者显示实际收取奖励；320/360/390/760/761/1440px 检查长昵称、大额完整金额及其他弹窗打开时的层级，不横向溢出、不阻断操作，不重复播放旧事件，遵循系统减少动态效果偏好。
- 运行后端相关规则与恢复测试、前端生产构建及浏览器端创建/配置/公屏专项回归，并记录本地截图与结果。部署与线上验收不属于本轮默认操作。
